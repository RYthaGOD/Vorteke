# Brand — VORTEX

_Status: documented (extracted from existing code, not run through the interactive picker)_

VORTEX already has a developed visual identity in `src/app/globals.css` and `src/components/DesignSystem.tsx`. This file documents what's there so it's the source of truth for future component work, instead of every new component reinventing colors ad hoc.

## Voice

Cyberpunk / industrial terminal. "Tactical," "recon," "uplink," "protocol" — a trading terminal that wants to feel like a hacker's mainframe, not a spreadsheet. Copy in the existing UI leans into this (`INITIATING_PROTOCOL`, `TACTICAL_RECON`) — keep that register for in-app system messages and states, but see the non-negotiables checklist: copy still needs to be concise and specific, not jargon for its own sake. User-facing errors and empty states should stay in-voice but remain plain enough that a first-time user understands them.

## Color

Defined as CSS custom properties on `:root` in `globals.css`. Always reference these tokens (`var(--accent-vortex-cyan)` or the Tailwind equivalents already wired up) — never hardcode hex values in components.

| Token | Value | Use |
|---|---|---|
| `--surface-obsidian` | `#050506` | Page background |
| `--surface-panel` | `#0a0a0c` | Card/panel background |
| `--surface-elevated` | `#121216` | Raised surfaces (modals, dropdowns) |
| `--surface-glass` | `rgba(5,5,6,0.7)` + `blur(24px)` | Glassmorphism panels |
| `--accent-vortex-cyan` | `#00F0FF` | Primary accent — links, active states, primary CTAs |
| `--accent-vortex-yellow` | `#E5FF00` | Secondary accent, success status, Solana-primary |
| `--accent-vortex-gold` | `#FFD700` | Elite tier accent |
| `--accent-vortex-red` | `#EF4444` | Error/danger status |
| `--text-primary` | `#FFFFFF` | Primary text |
| `--text-secondary` | `#A1A1AA` | Secondary text |
| `--text-muted` | `rgba(161,161,170,0.5)` | Muted/disabled text |

**Elite tier variant** (`.vortex-tier-elite` class): swaps primary→`#FFD700` (gold), secondary→`#A855F7` (purple) — used to visually distinguish Elite-tier token pages from Basic/Enhanced.

**Contrast note for the audit**: `--text-muted` at 50% opacity on `--surface-obsidian`/`--surface-panel` is likely to fail WCAG AA (4.5:1) for body text — check this specifically wherever `text-muted`/`vortex-text-muted` is used for anything that isn't purely decorative.

## Typography

| Token | Font | Use |
|---|---|---|
| `--font-main` | Outfit (300/400/600/700) | UI text, body copy |
| `--font-hud` | Space Grotesk (300–700) | Headers, HUD/status labels |
| `--font-data` | JetBrains Mono / Fira Code | Numbers, addresses, prices, code |

Loaded via Google Fonts `@import` in `globals.css`. Numbers and on-chain data (prices, addresses, token amounts) should use `--font-data` for tabular alignment — this is already the pattern in most of the token/portfolio components.

## Geometry

- **Radius**: `--radius-sharp: 0px` (default — industrial/sharp), `--radius-tactical: 2px`, `--radius-smooth: 8px` (used sparingly, e.g. avatars/badges).
- **Borders**: `--border-vortex` (subtle, `rgba(255,255,255,0.08)`), `--border-tactical` (accent-tinted, uses `--surface-glass-border`).
- **Shadow**: `--shadow-deep` for elevated panels/modals.
- **Grid background**: `--bg-grid` — faint cyan grid lines, used on data-heavy backgrounds (terminal page).

## Component conventions already in place

- Custom class prefix `vortex-*` and `btn-vortex*` (not shadcn/ui — this repo doesn't use shadcn). New components should follow this naming convention and use the existing `vortex-panel`, `btn-vortex`, `vortex-modal-*` classes rather than introducing a parallel component system.
- `DesignSystem.tsx` centralizes shared primitives (`VortexPanel`, `VortexButton`, `Modal`, `VortexLogo`) — extend these rather than writing one-off styled divs.
